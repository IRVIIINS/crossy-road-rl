## Headline results (3 seeds, 10,000 training episodes each, 200 held-out test seeds)

| Config | Test score (rows) |
|---|---|
| Double DQN + look-ahead (ours) | 25.5 ± 10.4 (seeds: 25.3, 15.1, 35.9) |
| vanilla DQN + look-ahead | 21.5 ± 1.2 |
| Double DQN, **no look-ahead** | 7.6 ± 0.7 |
| hand-written rule / always UP / random | 4.6 / 3.0 / 1.4 |

* **Look-ahead features are the big win** (about 3.4x): with only the present positions of cars and logs the agent barely beats a
  hand-written rule; with where they will be in 6 and 12 frames it triples its score. All three seeds agree.
* **Double DQN vs vanilla DQN: no reliable difference here.** The means differ by 4 rows but the Double-DQN runs vary a lot between seeds
  (15 to 36), so with 3 seeds you cannot claim Double DQN is better. Say exactly that in the report.
* High seed-to-seed variance of the full model is itself a finding (DQN is unstable; report mean +- std, not the best seed).
* Most deaths are "too slow" (36-43%), i.e. the agent waits too long for a gap and the idle limit ends the episode, rather than being hit.
* Early stopping: the ablation runs use `--patience 999` (no early stop) so all configs get an identical budget. In a first attempt with patience 10,
  a late-starting run was stopped before it began to learn; `train_iterative.py` now has `--min-iters 30` and `--patience 15` as safer defaults.

## Third AI: the level maker (second experiment)

| Player | Random levels | Level-maker levels | Drop |
|---|---|---|---|
| shipped agent (maker trained against it) | 22.6 | 7.6 | 67% |
| independent agent s0 / s1 / s2 (never seen by the maker) | 23.8 / 13.0 / 34.4 | 8.7 / 5.2 / 9.7 | 63% / 60% / 72% |
| hand-written rule | 4.3 | 2.2 | 47% |

* Three independently trained level makers all reached 6-8 rows for the player they trained against (down from about 20).
* It **generalises**: players the maker never saw also drop by about 60-70%, so it learned genuinely hard layouts, not one agent's quirk.
* **Fair by construction**: the maker never builds more than 3 road/river rows in a row (the random generator averages a longest run of
  5.8 and reaches 15), and all speeds are inside the original game's ranges.
* What it learned: it alternates fast rivers with grass (grass rows 44% vs 34% random, fast rivers 17%). Because of the even/odd rule, many of those
  rivers are lily-pad rows, i.e. it found a **weak spot of the player AI**: hopping onto exact lily pads. Honest wording for the report:
  "the level maker is adversarial to this class of agent", not "it makes levels that are hard for humans".
* Limits: trained against one player; the simulator ignores train tracks (the real game turns 1 in 4 road rows into rail).

## Honest framing that will read well

* Use **mean +- std over seeds** and the **held-out** test seeds (already done in `make_report.py`), not the best run.
* Say plainly that the real-game score is much lower than the simulator score (sim-to-real gap) and why.
* The shipped model (`models/expo_best.pt`) was trained for 20,000 episodes with `train_dqn.py`; the ablation runs use the
  shorter budget in `run_experiments.py`, so compare ablations with each other, not with the shipped model.
